# @thomasfosterau/effect-time

## 0.1.0

### Minor Changes

- [#12](https://github.com/thomasfosterau/effect-time/pull/12) [`c0756e2`](https://github.com/thomasfosterau/effect-time/commit/c0756e2e43c55a3fd5cc45a24df05143be22ca2f) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `CronExpression`: cron expressions (`30 9 * * MON-FRI`, six fields with seconds, and the `@daily`-style macros) parsed to Effect's `Cron`, equal to what `Cron.parse` gives for valid input, but failing with a positioned effect-parse `ParseError` that names the field. `parser`, `parserIn(timeZone)`, `parse`, `parseIn(input, timeZone)`, `format` and the `FromString` schema.

- [#2](https://github.com/thomasfosterau/effect-time/pull/2) [`f98567c`](https://github.com/thomasfosterau/effect-time/commit/f98567ce20cf46d77e1232dc4210a64fa38de882) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - First release: `Clock` and `DateTime`, Effect's own modules re-exported under one import, built to `dist/` with `exports` and declarations, `effect` as a peer. The `Date` re-export is gone: `effect/Date` does not exist in any Effect 4 release, so it never resolved.

- [#14](https://github.com/thomasfosterau/effect-time/pull/14) [`8c16c68`](https://github.com/thomasfosterau/effect-time/commit/8c16c6860eb80cdc0038299856b6687d9fc9b687) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `IanaTimeZone`: IANA time zone names (`Europe/Paris`) read with the tz database's naming rules and checked against the time zones the JavaScript runtime knows, with no bundled data. The answer depends on the runtime's ICU build. `parser`, `parse`, `known`, `isKnown`, `supported` (`Intl.supportedValuesOf("timeZone")`) and the `FromString` schema, decoding to the runtime's `DateTime.TimeZone.Named`.

- [#11](https://github.com/thomasfosterau/effect-time/pull/11) [`73c200a`](https://github.com/thomasfosterau/effect-time/commit/73c200ae8f80bd98ad052a0c9483b059227cad83) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `PosixTz`: POSIX TZ strings (`EST5EDT,M3.2.0,M11.1.0`, `<+1030>-10:30<+11>-11,M10.1.0,M4.1.0`), the `TZ` environment variable format and the TZif footer. `parser`, `parse`, `format` and the `FromString` schema read and print a `PosixTz` record: the standard and daylight designations, with UTC offsets in seconds east of Greenwich, and the daylight saving rule (`Jn`, `n` and `Mm.w.d` dates, with RFC 8536's extended transition times).

- [#3](https://github.com/thomasfosterau/effect-time/pull/3) [`5321689`](https://github.com/thomasfosterau/effect-time/commit/5321689a2b46119e4195dd13e820b501d45bb632) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Rfc3339` and `IsoDuration`, built on `@thomasfosterau/effect-parse`. `Rfc3339` parses RFC 3339 date-times into `DateTime` values: `parser`, `parse`, `format` and the `FromString` schema. `IsoDuration` parses ISO 8601 durations into the amounts `DateTime.add` takes: `parser`, `parse`, `format`, `FromString` and `zero`. `@thomasfosterau/effect-parse` (`^0.1.0`) is a new peer dependency. The `effect` peer floor rises to `^4.0.0`, because effect-parse requires it.

- [#4](https://github.com/thomasfosterau/effect-time/pull/4) [`2923c5f`](https://github.com/thomasfosterau/effect-time/commit/2923c5f8a64c1346529bb1727663eb552ed20b28) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Rfc9557`: RFC 9557 Internet Extended Date/Time Format (IXDTF) date-times, an RFC 3339 date-time with a time zone suffix (`[Europe/Paris]`, `[+05:30]`) and tagged annotations (`[u-ca=hebrew]`). `parser`, `parse`, `format` and the `FromString` schema read and print an `Ixdtf` record, and `toDateTime` views its instant in the suffixed time zone. A critical (`!`) time zone that is unknown or inconsistent with the written offset fails the parse.

- [#13](https://github.com/thomasfosterau/effect-time/pull/13) [`ed5cb0f`](https://github.com/thomasfosterau/effect-time/commit/ed5cb0fa985cb8bd0be64f73044e93ab88900c9d) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `RRule`: iCalendar recurrence rules, the RFC 5545 `recur` value of an `RRULE` property (`FREQ=WEEKLY;BYDAY=MO,WE,FR;COUNT=10`). `parser`, `parse`, `format` and the `FromString` schema read and print an `RRule` record: frequency, `UNTIL` as written, `COUNT`, `INTERVAL`, the `BY…` lists and `WKST`. Every value is range-checked and RFC 5545's cross-part restrictions fail the parse with a positioned error.

- [#15](https://github.com/thomasfosterau/effect-time/pull/15) [`17a0935`](https://github.com/thomasfosterau/effect-time/commit/17a0935736aabfdcc4afbe5783f5838e28428bf6) Thanks [@thomasfosterau](https://github.com/thomasfosterau)! - Add `Tzif`: an effect-parse binary parser for TZif files (RFC 8536, versions 1–4), the compiled zone files of the tz database. A `Tzif` holds the transitions, local time types (offset, DST flag, designation, standard/UT indicators), leap seconds and the POSIX TZ footer (as a `PosixTz`). The format's structural requirements are checked, and a violation fails at its byte offset. `parser` and `parse`.
